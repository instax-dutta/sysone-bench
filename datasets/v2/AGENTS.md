# Purpose
- Owns the v2 public-source registry, resolved source lock, deterministic inventory builder, and draft manifest writer.
- Owns v2 dataset artifacts, including the current provisional manifest/provenance draft, blind packets, the approved single-review AI-assisted label export, and final seal records.
- Keeps the v2 boundary separate from the legacy dataset files and result records.

# Ownership
- `sources.py` owns source IDs, canonical and wrapper names, splits/configs, and deterministic sampling helpers.
- `sources.lock.json` owns the resolved public-source revisions, licenses, and citations.
- `build_manifest.py` owns the approved provisional inventory, core-schema record construction, provenance sidecar, draft manifest serialization, and application of the approved split assignment.
- `validate.py` owns deterministic split assignment, dataset counts and split gates, external row-provenance validation, checksum verification, normalized-state duplicate rejection, and near-duplicate diagnostics.
- `tools/build_dataset_v2.py` is the clean-environment entry point that imports external `datasets` before extending its package path to the local v2 module.
- `labeling.py` owns blind reviewer packet generation, direct-label export validation, agreement statistics, disagreement-only adjudication, reviewer/adjudication merge, final manifest sealing, and the module CLI handoff.
- `assistant.py` owns the local Cerebras draft assistant, sanitized suggestion requests, the dark approve/re-pass interface, and the separate assistant-confirmed download; it never writes official reviewer or seal artifacts.
- `assisted_labels.py` owns the approved single-review AI-assisted label protocol, strict assistant-export parsing, the pure assisted merge, the canonical-root finalization transaction, and its own module CLI. It never creates or implies two-reviewer artifacts.

# Local Contracts
- Public-source records must preserve canonical name, wrapper, a lowercase full 40- or 64-character hexadecimal commit revision, split, config when applicable, license, and citation. Reject mutable refs, abbreviated hashes, and non-hex revisions; represent missing license metadata explicitly.
- `SOURCES` and `sources.lock.json` must contain the same source IDs and metadata. The `banking77` source ID is the source for the `banking77_12` suite.
- Dataset seed is `42`. Suite-specific seeds use SHA-256 of `f"{base_seed}:{suite_id}"` and the first eight digest bytes in big-endian order. Sampling uses a local seeded RNG, preserves source rows, and does not mutate inputs.
- Public v2 provenance must retain source ID, canonical source, wrapper, resolved revision, split/config, original row ID, source label, local modification, license, citation, and checksum in `provenance.json`; core manifest records retain only the schema-approved `provenance_id` and `label_provenance` fields.
- Split assignment stratifies only by the approved primary decision/class field for each suite, with language-intent pairing for multilingual cases, and uses deterministic largest-remainder allocation for non-divisible quotas.
- The builder writes an explicitly provisional label state, applies the approved stratified split to copied records before draft validation, and never mutates caller-owned construction data.
- `validate_dataset` requires the core manifest contract, exact suite and decision counts, exact 238/952 split totals, complete public row provenance from the sidecar or an explicit registry, and deterministic checksums when source rows are available.
- Manifest records never contain nested provenance; row-level provenance remains in `provenance.json` or an explicitly supplied equivalent registry, and missing public registry entries fail validation.
- `normalized_state` uses sorted-key compact UTF-8 JSON with non-finite values rejected; exact duplicates fail and near-duplicate clusters are reported without deleting or relabeling cases.
- The manifest writer validates the complete record list with `benchmark.manifest`, writes canonical JSONL atomically, returns the full manifest digest, and refuses to replace `manifest.sha256`-sealed output.
- Never overwrite `datasets/cases.py`, `datasets/public_cases.json`, legacy result JSONs, or any sealed v2 artifact. Do not run model inference or access credentials from this data boundary.
- Manifest expected values follow question type: legal choice strings, exact integer 0/1 noul values, and finite numeric score levels within each declared range. Reviewer exports continue to use direct labels without post-hoc model outputs.
- Blind reviewer packets expose only case ID, recursively sanitized user state, ordered question text/type/allowed answers/range, neutral instructions, and local packet controls. Sanitization removes ground-truth, gold/truth/reference/final/adjudicated, human/annotation/annotator, answer-key/class-label/weak-label/supervised/supervision, provenance, model/result, suite/dataset/schema, split/calibration/evaluation, revision/checksum/license/citation/row, and label metadata key families recursively while preserving message, prompt, post, text, language, premise, and hypothesis state keys; bare and normalized/prefix variants of class and weak are blocked; state and question text must be escaped before embedding.
- Reviewer packets use a dark, high-contrast theme with visible keyboard focus states; theme changes must not alter blind content, export schema, or local drafts.
- The assistant reads only `CEREBRAS_API_KEY` from the environment for HTTP mode, uses `ASSISTANT_PROVIDER=opencode` with `ASSISTANT_MODEL` for OpenCode mode, sends sanitized case state and question data, and exports `assistant_confirmed.json` separately from official labels; API suggestions require explicit local approval and re-pass calls never advance the case.
- Assistant prefill writes only `assistant_prefill.json`, checkpoints atomically, resumes by `(case_id, qid)`, retries transient provider failures, and refuses official label/seal filenames; the review page loads that draft as initial suggestions and never treats it as a completed human export.
- The current `manifest.jsonl` and `provenance.json` are provisional Task 6 draft artifacts. The approved finalization path is the single-review AI-assisted protocol below; the blind packets remain available, but no `labels/` export, provisional backups, or `manifest.sha256` exist yet.
- The approved dataset label protocol is one human reviewer who reviews and corrects AI draft answers, recorded as label provenance and protocol id `human-reviewed-ai-assisted-v1`. It replaces the two-independent-reviewer requirement for this dataset and must be disclosed in the final provenance. The two-reviewer path in `labeling.py` stays intact and is the only path that produces reviewer, adjudication, and `adjudicated-v2` artifacts.
- Adjudication downloads preserve both reviewer label sets and empty required reason inputs alongside final labels; untouched empty reasons fail validation. The two-reviewer path must not be sealed while any reviewer disagreement is unresolved, and no completion may be claimed until the required human exports and adjudication artifacts exist.
- `merge_adjudication` requires exact case/question coverage for reviewer A and B, exact disagreement-only coverage in the schema-2 adjudication payload, exact preserved reviewer labels, and a legal nonempty final label and reason for every disagreement. It deep-copies records, preserves record and question order, and sets `label_provenance` to `adjudicated-v2`.
- `seal_manifest` requires `manifest.jsonl`, `provenance.json`, `labels/reviewer_a.json`, `labels/reviewer_b.json`, and `labels/adjudication.json`. The provenance sidecar must contain `provisional` with exact boolean value `true`; missing keys and truthy or false-like non-booleans fail, while boolean `false` identifies a finalized sidecar that must never be overwritten. The merged records pass the complete `validate_dataset` gates with the supplied sidecar registry.
- Sealing holds the exclusive per-output-root `.manifest.seal.lock` across input validation, staging, checksum creation, and draft replacement. Recheck the seal under the lock, exclusively create `manifest.sha256` with exactly `<digest>  manifest.jsonl\n` before replacing either draft, then atomically replace the canonical manifest and finalized provenance. On failure, remove only lock, checksum, and temporary files created by that operation and restore any draft it replaced.
- The two-reviewer seal refuses an existing `manifest.sha256`, active seal lock, or finalized sidecar. Human reviewer and adjudication files must come from the Task 6 handoff; implementation tests using synthetic temporary exports do not satisfy that prerequisite or establish dataset completion.
- The assisted export envelope is strict: exactly `schema_version`/`source`/`official_labels`/`model`/`entries`, `schema_version` 1, `source` exactly `cerebras-assistant`, `official_labels` exactly boolean `false`, nonempty model, and `entries` a list of objects with exactly `case_id`/`qid`/`answer`/`question_type`/`model`. Every entry matches one manifest question exactly once with a matching `question_type`, and the export covers every manifest question.
- `apply_assisted_review` is pure: it deep-copies records, replaces expected values, sets every record's `label_provenance` to `human-reviewed-ai-assisted-v1`, preserves record order, state, questions, splits, and provenance IDs, never mutates its inputs, and finishes with `benchmark.manifest.validate_manifest` so every choice, noul, and score value must be legal.
- `finalize_assisted_dataset` operates only on the canonical `datasets/v2` root. It requires `manifest.jsonl`, `provenance.json`, and the assistant export as regular non-symlinked files; refuses an existing `manifest.sha256`, a sidecar whose `provisional` is not exact boolean `true`, a finalized sidecar, or existing `manifest.provisional.jsonl`/`provenance.provisional.json` backups; and requires exactly 1550 reviewed questions and applied entries.
- Finalization preserves the original bytes as `manifest.provisional.jsonl` and `provenance.provisional.json`, copies the exact export bytes to `labels/assistant_confirmed.json`, calls the complete `validate_dataset` gates with the finalized provenance as both sources and registry, requires the validator digest to equal the logical manifest digest, exclusively creates `manifest.sha256` containing exactly the raw manifest-file SHA-256 plus `  manifest.jsonl\n`, then atomically replaces the canonical manifest and provenance. It uses same-directory temporary files with fsync, and on failure restores the canonical originals and removes only artifacts that operation created. It never writes `labels/reviewer_a.json`, `labels/reviewer_b.json`, or `labels/adjudication.json`.
- Finalized provenance sets `provisional` to `false` and adds a top-level `label_review` object recording the protocol id, `reviewer_count` 1, `independent_human_review` false, `adjudication` false, the assistant model, the assistant export SHA-256, the 1550 question and entry counts, and a concise method statement that one human reviewer reviewed and corrected the AI draft answers.
- The assisted CLI accepts only `--output` and `--assistant`, rejects their resolved-path or `(st_dev, st_ino)` identity collision, delegates to `finalize_assisted_dataset`, and prints only the full digest. Its errors use the same fixed-term allowlist style as the labeling CLI; arbitrary paths, JSON keys, label values, and unknown flag text are never echoed.
- Agreement summaries are suite-scoped before question-level aggregation, and multilingual records must carry a valid `state.language`.
- Calibration cases are for calibration work only and must never contribute to headline accuracy or other headline evaluation metrics.
- Review packets (`reviewer_a.html`, `reviewer_b.html`, `assistant_confirmed.html`) are generated on demand and are never committed. Each is over 2 MB, and the sealed inputs they are built from are already in this directory.
- The module CLI supports blind packet, agreement, and seal handoffs. Packet mode accepts only records/output and writes only `reviewer_a.html` and `reviewer_b.html`; agreement mode accepts optional records plus reviewer-a/reviewer-b/output/report and writes canonical report JSON plus disagreement-only HTML; seal mode accepts only output/records/reviewer-a/reviewer-b/adjudication, delegates to `seal_manifest`, and prints only the full digest. Before any write, reject mode-incompatible flags and resolved output/report collisions with records, reviewer exports, adjudication, manifest, and each other using canonical paths plus existing `(st_dev, st_ino)` identity; packet output must not be an existing file, agreement output/report must not be existing directories, and the HTML packet is written before the agreement report. Seal input paths remain fixed under the output root. Strict UTF-8 JSON readers reject malformed input and report duplicate object keys generically. CLI errors use a fixed-term formatter that preserves only allowlisted diagnostic terms and known option names; arbitrary paths, JSON keys, label values, and unknown flag text are never echoed. Path-resolution failures remain concise and redacted.
- Packet destinations are preflighted together before either is staged. Packet and agreement artifacts use same-directory temporary files and a rollback/commit helper; a failed operation preserves pre-existing target bytes, removes newly created targets, and cleans only owned temporary files. Seal mode retains its exclusive and append-only rules.

# Work Guidance
- Keep the registry and lock synchronized when adding a public source; require an explicit resolved commit and license/citation record.
- Preserve exact source distinctions and provenance rather than normalizing raw source identity.
- Use the suite-specific seed and a local seeded RNG for every public-source sample; never mutate source rows or legacy files.
- Run dataset downloads and other batch work on the approved remote worker, not locally.
- Do not start model runs until a future v2 manifest is complete, reviewed under the approved label protocol, and sealed.
