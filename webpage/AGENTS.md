# webpage

## Purpose
- Static public site for sysone-bench, served at `https://sysone.sdad.pro/`.
- Presents published benchmark results to humans and to AI answer engines.

## Ownership
- Owns site structure, copy, visual design, generated site data, GEO files, and the GitHub Pages deploy config.
- `index.html`, `style.css` and `app.js` are the rebuilt "measurement ledger" site: paper ground,
  ink typography, one oxide-red accent, data rendered at load time from `data/results.json`.
- `template.html` is the source page; `prerender.py` renders it into `index.html` from generated data at publish time. Never hand-edit `index.html`.
- `visuals/scenes.py` owns the ManimGX scenes. `assets/*.mp4` and `assets/*-poster.png` are rendered
  from `data/results.json`; regenerate them after a data change with `manimgx render`, then
  `manimgx inspect` first. The scene sources and evidence live in `redesign/`, not in Skill dirs.
- `fonts/` owns the self-hosted IBM Plex Mono and Newsreader WOFF2 files and their OFL licences.
  `index.html` must not request fonts from a CDN.
- `public-artifacts/seb-9b-t4/` is the public, byte-for-byte copy of one complete run directory.
  Its `checksums.sha256` and run files are the record; `index.html` is site navigation and is not
  listed in the checksum manifest. Never type a score into that index.
- `prerender.py` also generates the best-by-task strip, visible FAQ answers and sr-only data tables
  from `data/results.json`. Those fragments carry current figures and must never be hand-edited.
- Does not own result artifacts, ground truth, coverage rules, or model adapters. Those belong to
  `results/`, `datasets/`, `ops/`, and `runners/`.

## Local Contracts
- No framework and no build step. Files ship as-is; there is no bundler, transpiler, or package.json.
- `data/results.json` is generated. Never edit it by hand. Regenerate with `python webpage/build-data.py`.
- `build-data.py` must stay runnable from any working directory. It resolves `ops/panel_coverage.py`
  relative to its own file, not the caller's cwd.
- `build-data.py` reads only checksum-verified run directories. A failing checksum drops the
  measurement rather than publishing it.
- Counts come from `ops/panel_coverage.py` so the site cannot drift from the repository's coverage
  number. Never hand-type a count, score, or total into markup.
- Copy counts use `<span data-count="key">`. `app.js` fills them from `results.json` using the keys
  `measurements`, `dirs`, `decisions`, `suites`, `scope`, `unmeasured`. The inner text is only a
  no-JS fallback and is expected to drift; it is never the source of truth.
- Share metadata in `<head>` and anything inside JSON-LD cannot be data-driven in a buildless site.
  Those must carry no count or score that changes when a model is added. Keep them method-level.
- Site counts must stay internally consistent: 50 distinct measurements, 53 verified run directories,
  50-entry scope, so 0 entries are unmeasured. Every entry that is not measured needs a recorded reason in
  `webpage/build-data.py` `EXCLUDED_NOTES`, which emits `excluded` into `results.json` for `app.js`
  and `tools/build_llms.py` to read. There is no second hand-maintained list; adding an entry to
  `app.js` directly is a bug.
- `llms.txt` and `llms-full.txt` are generated by `tools/build_llms.py` from `data/results.json`.
  Never hand-edit either file and never type a count, score, digest or rank into them; that is how
  `llms.txt` came to advertise the 2.0.0 manifest digest and pre-correction scores while the site
  served 2.1.0. Regenerate with `python webpage/build-data.py && python tools/build_llms.py` after any
  data change.
- No-JS fallbacks in `index.html` use `<span data-count="key">` and are expected to drift, but they
  must still be corrected when noticed: a stale fallback is the only wrong number a crawler or a
  reader with JS disabled will ever see.
- A measurement that declined to answer must carry its `deferrals` block from run metadata, render a
  "declined" pill in the ranked list, and state the declined share in the selected-model note. The
  decision contract has no abstention type, so every declined decision is answered at argmax by the
  adapter and counted as a confident answer the model did not choose. Never hand-add this; it is
  derived in `build-data.py` from `metadata.deferrals`.
- A measurement whose artifacts cannot be reproduced is withdrawn from the ranking and listed in
  `EXCLUDED_NOTES` with the reason. Never publish it from a superseded run instead.
- The site brands itself only as `sysone-bench`. Do not add external panel, leaderboard, or edition
  attribution to site copy, `llms.txt`, or the generated data keys.
- The closed-API reference is drawn as a labelled rule or row, never merged into the open-weights ranking.
- No composite or averaged cross-suite score. No radar chart. Suite spread is shown per suite instead.
- Truncated axes must state the truncation on the chart itself.
- A measurement whose scoring path is listed in `READOUT_CAVEAT_PATHS` in `build-data.py` must carry
  `readoutCaveat: true`, derived from the run's own scoring field. Never hand-list runner names.
- An unresolved measurement-validity question must be published as a caveat on the affected rows
  rather than left implicit, and must state what is confirmed versus merely suspected. Adding a
  caveat changes no number and requires no re-run; say so on the page.
- Charts are hand-built inline SVG in `app.js`. Keep them accessible: `role`, `aria-label`, and a
  `<title>` per mark.
- No CDN script runtime. `index.html` loads Google Fonts plus the locally vendored
  `vendor/lenis.min.js` (MIT, Lenis 1.3.27) before `app.js`; no other script dependency is allowed.
  Do not add scroll-triggered reveal or bar-grow animations: staggered opacity and transform changes
  on long lists create a translucent band that moves with the viewport and looks like a broken bar.
- Smooth scrolling is owned by Lenis in `app.js` with `autoRaf: true`; it must be skipped under
  `prefers-reduced-motion`, where anchor links fall back to native `scrollIntoView`. Nested chart
  wrappers carry `data-lenis-prevent` so their horizontal scrolling stays native.
- `html` keeps `scroll-behavior: auto` and `overscroll-behavior-y: none`; Lenis smooths the native
  scroll position rather than transforming the page, so sticky layout still works. Anchor targets have
  `scroll-margin-top` under the sticky masthead.
- Wide fixed-pixel charts live inside an `overflow-x: auto` wrapper so they stay scrollable on narrow
  viewports. The text-heavy charts (`#chart-strip`, `#chart-suites`, `#chart-precision`,
  `#chart-coverage`) keep a `min-width` on narrow screens inside `.scroll-x` so their axis labels stay
  legible instead of scaling to a few pixels. Page-level horizontal overflow must stay false.
- Content stays fully opaque while scrolling in both normal and `prefers-reduced-motion` modes.
  No content may be left stranded invisible, and no animation may run on ledger rows or their bars.
- The hero video is lazy: `source` elements carry `data-src` until `app.js` observes the film in
  view. Reduced motion or missing codecs keep the settled poster and add `no-video` for the scan
  fallback. The video must not block first paint.
- Ledger rows are clickable run-record drawers with full revision, run ID, device, dtype, serving,
  readout and caveats. Checkboxes shortlist up to three models; the comparison is per-suite deltas
  against the first selection. No overall or averaged score may be introduced.
- Every SVG chart has a generated `table.sr-only` equivalent referenced by `aria-describedby`.
- No secrets, tokens, or keys in this directory. `CNAME` carries the custom domain only; the
  deploy workflow is owned by `.github/workflows/deploy-pages.yml`.
- `favicon.svg` is the icon source of truth. `icon-512.png` and `apple-touch-icon.png` are rasters of
  it, and the touch icon must stay full-bleed because iOS applies its own mask.
- `og.png` is a static PNG, so anything printed on it goes stale the moment another model lands.
  It must therefore claim **no volatile fact**: not the measurement count, not the best open score,
  not any ranking or top-N. It carries only the stable method facts: sealed case count, scored
  decisions per model, closed-API reference, seed. Do not add a count back without also solving
  per-deploy card regeneration.
- Never draw a magnitude the data does not support. Equal-length bars for the nine suites were
  removed for exactly this reason; the suites are listed as a ruled list instead.
- Never type a score into the card by hand. It is 1200x630 and nothing may overflow that frame or
  collide with the footer rule; assert both.
- `llms-full.txt` is generated from `data/results.json` by `tools/build_llms.py`, together with
  `llms.txt`. It is the single self-contained answer source for AI engines and must never be
  hand-edited or left to drift from the site. Regenerate it whenever the data changes, alongside
  `og.png`.
- Every path declared in a `<link rel="icon">`, `apple-touch-icon`, or `og:image` tag must resolve to a
  committed file. An advertised-but-missing `og.png` is a broken share card, so verify each returns
  HTTP 200 after adding it.

## Work Guidance
- Design direction is the measurement ledger (approved in `redesign/DESIGN.md`): warm paper, ink
  typography, hairline rules, one oxide-red accent. No glow, gradients, cards, shadows, or dark
  developer-tool template.
- Type: Newsreader or Iowan Old Style serif for display and lede, IBM Plex Mono for every number,
  label and axis. Numerals are the primary graphic; the headline score is set over 100px.
- Colour is meaning: `--oxide` for measured values and the closed-reference comparison, `--rule`
  for hairlines, `--muted` for secondary copy. Technique rows are dimmed through SVG opacity, not a
  second accent.
- The first screen is the headline measurement plus the animated ledger film, then the proof strip.
  The masthead is one compact row with the dataset version.
- The ranked field is `.ledger` / `.ledger-row`, not a card grid: rank, name, score, nine-suite
  sparkline, provenance flags. `app.js` renders all rows from `data/results.json`.
- `app.js` owns SVG geometry and fills. CSS owns layout only. Do not set SVG `fill` in CSS.
- Section headings use the eyebrow mono label; charts sit inside a single hairline border.
- Content is static on scroll: a full-page capture, a crawler and a live reader all see the same
  fully opaque section. Only the hero film and its codec-free scan fallback animate.
- Run a local static server for preview. `file://` will not work because `app.js` fetches the data file.

## Verification
- `node --check webpage/app.js` for syntax.
- Preview on `http://127.0.0.1:8899`. Console must be clean.
- Check at 1280px and 390px: page-level horizontal overflow must be false at both, and
  `.heatmap-scroll` must still scroll.
- `manimgx inspect webpage/visuals/scenes.py <Scene>` must report no layout problems before any
  render; both MP4s and their posters must be committed.
- Walk the full page at both widths and confirm no `.reveal` is left below full opacity, in both
  normal and `prefers-reduced-motion` modes.
- Exercise both leaderboard sort directions, both suite compare modes, and the model selector. The
  compare-top-5 view is the only place five data colours appear, so it is the regression check for
  the bar-fill layering.
- Confirm `build-data.py` reproduces `data/results.json` byte-identically apart from intended key changes.
- Confirm `tools/build_llms.py` is deterministic, and that every 4dp figure in both GEO files resolves
  to a value in `results.json`. The one permitted exception is a withdrawn measurement's old score,
  which may appear inside its `EXCLUDED_NOTES` reason to document what was pulled.
- Verify the deferral note appears for a deferring model and hides for one that does not, through both
  the ranked-list click and the `#suite-model` select. Step through several scroll positions and assert
  `document.getAnimations()` is empty for ledger rows and their bars, so no translucent band moves
  through the bottom of the viewport.
- Confirm `html` gains the `lenis` class in a normal browser, `window.lenis` exists, anchor clicks use
  `lenis.scrollTo`, and with reduced motion the class is absent and anchors fall back to native scroll.
- Confirm the text-heavy charts keep a legible `min-width` at 390px inside `.scroll-x`, and that the
  page-level horizontal overflow stays false at both widths.
- Verify `favicon.svg`, `icon-512.png`, `apple-touch-icon.png`, `og.png` and `llms-full.txt` all
  return HTTP 200, and that the icon is legible at 16px.
- `llms.txt` must link `llms-full.txt`, and the counts quoted in both must match `results.json`.
- Grep the directory for removed branding before publishing.
